# 数据规则与 Schema v2

实际表定义位于 `lib/data/database/app_database.dart`，Schema 快照位于 `lib/data/database/migrations/drift_schema_v2.json`。业务校验由相应仓库实现，SQLite 外键、唯一键和金额 CHECK 提供第二道约束。

## 金额、币种与日期

- 金额保存最小单位整数；人民币 12.34 存为 1234。输入从字符串按位解析，不使用 double 乘 100。收入 / 支出 / 往来金额必须为正，物品价格允许 null 或零，初始余额允许负数。
- 支持 CNY / USD / EUR / GBP / HKD 两位小数、JPY 零位。账户独立币种，统计 / 预算 / CSV 按币种分组。转账只允许同币种不同账户。
- 业务日期为本地 `YYYY-MM-DD` 文本，不随着时区改变月份；创建 / 修改时间是 UTC 毫秒。月查询为月初包含、下月月初不包含。
- 物品持有天数按 UTC 构造的日历日差 + 1，包含购买当天，避免夏令时对日数的影响；未来购买日期拒绝。

## 表和关系

| 表 | 用途 |
| --- | --- |
| accounts | 名称、渠道、类型、币种、初始余额 |
| categories | 收支分类；名称与类型组合唯一 |
| entries | 七种交易类型、正整数金额、账户、可选转入账户 / 分类 / 原债务、日期备注、审计时间 |
| budgets | 月份与币种联合主键、预算整数金额 |
| items | 名称、独立物品分类、可选价格 / 日期 / 图片、币种、备注、审计时间 |
| purchase_links | 物品与支出联合主键；删除任一端仅级联删除关系 |
| preferences | 当前包含 system / light / dark 外观偏好 |

记录采用 UUID；初始内置分类使用稳定的 expense-N / income-N ID。日期与账户设查询索引；所有数据库连接开启 foreign_keys。

账户有流水后不能删除、改币种或改初始余额。分类有记录后不能删除，也不能改变收支类型。转账减少源账户、增加目标账户，不进入收入支出。借入增加现金与待偿还本金；借出减少现金与增加待收回本金。还款必须关联对应币种和借贷类型，日期不早于借贷，累计不得超过本金；已有还款的原债务不得删除。

## 物品、照片与购买关联

物品可以完全独立。关联仅允许同币种支出，同一物品 / 支出对唯一；可多对多。购入价由用户显式录入，关联或编辑支出不会覆盖物品价格，不能把一笔购买金额自动重复分配给多件物品。日均成本仅展示有价格及日期的物品，用价格除以含首日的持有天数。

每件物品当前一张图片，选择 / 拍照限制约 2048 像素、导入上限 10 MB。选择器临时结果复制为私有 `media/<UUID>` 文件，数据库只存相对路径。保存失败 / 取消可能留下孤立照片，媒体服务清理超过一天且无引用的文件。删除账目或物品不删除另一端；解除关联事务提交后原图延迟清理。

Android retrieveLostData 在物品页面首次打开时处理，恢复照片交给用户完成新的物品表单；原未保存的其他输入字段不保证恢复。

## 备份与演进

当前采用 ZIP + manifest + 逻辑 JSON + 原图，替代早期复制数据库文件 / 多文件切换的建议。全量读事务创建快照；恢复先隔离验证、发布新图片，再通过单一 SQLite 事务替换所有逻辑行。详细限制、故障保护和测试边界见 [备份协议](backup-format.md)。

Schema 与备份格式版本独立维护，目前数据库为 2、备份容器为 1。已验证 v1 数据库迁移与旧逻辑备份兼容；后续变更继续补齐迁移及失败测试。不记录金额、备注、原图或备份正文到日志；测试使用人工数据。

0.2.0 的资产、图表和归档新规则以 [产品调整](../product/revision-0.2.md) 为准。
