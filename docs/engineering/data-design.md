# 数据设计原则

本文约束后续建模，不是已实施 Schema。分类、默认货币、关联分摊与备份加密仍待产品确认。

## 金额与时间

- 金额保存为最小货币单位的整数，例如人民币 12.34 元存为 1234 分。输入从字符串按位解析，不经过 `double * 100`；累计和减法保持整数计算。
- 收入 / 支出是独立类型，录入金额为正整数；不以负数编码支出。可选物品价格允许空值，空值与零不同；免费物品可为零。
- 第一版按单一货币设计，币种与小数位数在实现前确认。备份记录币种，不跨币种直接求和；多币种及汇率不属于 MVP。
- 财务发生日期优先作为本地日历日期保存（如 `YYYY-MM-DD`），保证迁移 / 时区变化不会移动到另一月份。若后续需要时分，单独补充模型与时区约定。
- 创建 / 修改时间保存 UTC 时间戳；用户业务日期与系统审计时间分开。月份查询采用月初包含、下月月初不包含的区间。

## 实体与关联草案

| 实体 | 用途与约束 |
| --- | --- |
| ledger_entries | 收入 / 支出、整数金额、分类、业务日期、备注、审计时间 |
| ledger_categories | 收支分类的稳定 ID，类型与账目类型一致；初期是否可编辑待定 |
| items | 名称、物品分类、可选购买价格 / 日期、备注、审计时间 |
| item_categories | 独立于财务分类，避免把餐饮消费分类当成物品分类 |
| item_photos | 物品 ID、相对文件路径、排序；为一件物品多照片留出关系结构 |
| purchase_links | 支出 ID 与物品 ID 的关联；同一对 ID 唯一，关联双方必须存在 |

每个实体采用稳定 UUID。外键校验开启，查询索引按真实的日期 / 分类 / 名称搜索需求设计，不提前创建大量索引。Schema 从 Phase 1 的必要表开始，后续功能通过迁移增加表。

PRD 支持一笔支出关联多个物品，但没有明确一个物品能否关联多次购买。关系表保留扩展能力，第一版允许的基数和重复关联规则在 Phase 3 前确定。维修和出售关联后续另行建模，不混入购买关系。

建议的删除语义：删除账目或物品时，同一事务删除其关联行；保留另一侧实体，不联动删除。此为待确认的交互默认方案。删除物品还需清理照片引用，文件清理在数据库提交后完成并支持重试。

从账目创建物品时，价格 / 日期 / 备注是录入默认值，不是永久镜像。关联账目的金额变化不自动覆盖物品价格。多物品分摊方案未确定前，不把整笔支出重复计为每件物品成本，也不推出持有成本统计。

## 图片生命周期

- 选择器返回的临时图片先复制到应用私有媒体目录，再保存引用；不长期引用相册路径或选择器缓存。
- 数据库只存相对媒体路径或媒体 ID。应用运行时解析绝对路径，避免 Android / iOS 或重装后路径变化。
- 将用户照片与打包 `assets/` 分开。缩略图是可重建缓存，完整备份包含原始媒体。
- 文件系统操作不属于 SQLite 事务。新增时先写入暂存文件，完成文件发布后提交引用；数据库失败留下的孤立文件可清理。删除时先提交引用删除，再清理无引用文件。
- 原图处理与备份压缩避免阻塞 UI；实现时明确照片尺寸、支持类型与数量限制。

## 备份协议草案

建议使用单个 ZIP 包，包含 `manifest.json`、一致性 SQLite 快照和 `media/`。CSV / 独立 JSON 是后续外部分析导出，不能替代全量备份。

manifest 记录：备份格式版本、数据库 Schema 版本、应用版本、UTC 导出时间、币种、每个文件的相对路径 / 字节大小 / SHA-256。加密未确定，不应承诺 ZIP 自带保护。

导出暂停写入并通过 SQLite 快照机制生成完整数据库，验证快照后打包；不能直接复制仍在写入的数据库主文件而遗漏 WAL 中的数据。数据库快照与媒体清单必须属于同一份逻辑快照。

恢复第一版建议采用全量替换，暂不做合并；这是待确认的产品默认方案。执行前说明将替换现有数据及当前备份是否加密，并要求用户确认，文件选中不等于允许覆盖。

恢复顺序：

1. 解包到隔离暂存目录，拒绝绝对路径、路径穿越、重复路径及超出限制的解压体积 / 文件数量。
2. 校验格式版本、摘要、必需文件、SQLite 完整性、外键和图片引用。未知未来版本拒绝导入；旧 Schema 先在暂存数据库迁移，不修改现有库。
3. 保留当前完整数据作为回滚副本，关闭连接、暂停写入，将验证通过的数据库和媒体作为一个数据集切换。
4. 重新打开并检查成功后刷新 provider；失败恢复旧数据集。
5. 多文件切换不能视为单次原子操作：使用活动数据集指针与恢复日志，启动时识别中断并完成或回滚切换。通过故障注入验证各中断点后再交付。

校验摘要用于检测损坏，不证明来源可信。备份上限、媒体上限及安全解包规则在实现前制定；在内存受限的 Android 真机验证大数据量。

## 迁移与测试约束

数据库 Schema 版本和备份格式版本独立维护。每次 Schema 变更提交迁移、快照与历史版本升级验证；不以删除数据库作为生产迁移方案。金额边界、跨月统计、关联一致性、照片清理、损坏备份、未来版本拒绝与恢复中断是关键测试内容。

日志不输出金额、备注、图片内容或备份数据；测试样例使用人工数据。
