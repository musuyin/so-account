# 数据规则与 Schema v9

实际表定义位于 `lib/data/database/app_database.dart`，Schema 快照位于 `lib/data/database/migrations/drift_schema_v9.json`。业务校验由相应仓库实现，SQLite 外键、唯一键和金额 CHECK 提供第二道约束。

## 金额、币种与日期

- 金额保存最小单位整数；人民币 12.34 存为 1234。输入从字符串按位解析，不使用 double 乘 100。收入 / 支出 / 往来金额必须为正，物品价格允许 null 或零，初始余额允许负数。
- 支持 CNY / USD / EUR / GBP / HKD 两位小数、JPY 零位。账户独立币种，统计 / 预算 / CSV 按币种分组。转账只允许同币种不同账户。
- 业务日期为本地 `YYYY-MM-DD` 文本，不随着时区改变月份；创建 / 修改时间是 UTC 毫秒。月查询为月初包含、下月月初不包含。
- 物品持有天数按 UTC 构造的日历日差 + 1，包含购买当天，避免夏令时对日数的影响；未来购买日期拒绝。

## 表和关系

| 表 | 用途 |
| --- | --- |
| accounts | 名称、类别、类型、自定义类别名、币种、初始余额、头像、可选银行 ID、可选买入单价、归档状态 |
| balance_adjustments | 账户、调整前后余额、差额、业务日期、原因、创建时间；非交易记录 |
| wish_goals | 心愿/攒钱目标、币种、目标金额、截止日期、优先级、状态及备注 |
| goal_contributions | 目标关联、带方向的金额、业务日期、备注、创建时间；独立进度，不改变账户余额 |
| categories | 收支分类；名称与类型组合唯一 |
| entries | 七种交易类型、正整数金额、账户、可选转入账户 / 分类 / 原债务 / 债务账户、日期备注、审计时间 |
| budgets | 月份与币种联合主键、预算整数金额 |
| items | 名称、独立物品分类、可选价格 / 日期 / 图片、币种、备注、审计时间 |
| purchase_links | 物品与支出联合主键；删除任一端仅级联删除关系 |
| preferences | 当前包含 system / light / dark 外观偏好 |

记录采用 UUID；初始内置分类使用稳定的 expense-N / income-N ID。日期与账户设查询索引；所有数据库连接开启 foreign_keys。

账户有流水后不能改币种或改初始余额。归档保留全部历史，退出当前资产汇总与新记账选择，恢复沿用原 ID 和余额；永久删除会在一个事务中清理相关流水、借贷结算及余额调整，仅移除物品关联，保留物品。详见 [账户归档与永久删除](../product/account-archive.md)。分类有记录后不能删除，也不能改变收支类型。转账减少源账户、增加目标账户，不进入收入支出。借入增加现金与待偿还本金；借出减少现金与增加待收回本金。还款必须关联对应币种和借贷类型，日期不早于借贷，累计不得超过本金；单独删除已有还款的原债务仍会被拒绝。

资金、信贷、充值、投资理财和债务分别维护允许的账户类别。旧往来人按名称、币种和应收/应付方向迁移为账户，原借贷及偿还记录保留并关联同一债务账户。应付款正余额在净资产中取负，应收款及报销正余额取正，避免重复累计旧人员往来。投资单价为精确十进制文本，只记录成本，不读取行情。

账户余额等于初始余额、交易影响和余额调整差额之和。余额调整在事务中核对调用方看到的余额及币种，发生变化则拒绝保存；允许零及负余额。调整不改初始余额、不写交易、不影响收支和预算，资产曲线从业务日期计入差额；独立记录保留调整前后余额和原因。债务余额调整只修正账户汇总，不改分笔借贷剩余本金。有调整记录的账户同样不能改币种或初始余额。

## 物品、照片与购买关联

物品可以完全独立。关联仅允许同币种支出，同一物品 / 支出对唯一；可多对多。购入价由用户显式录入，关联或编辑支出不会覆盖物品价格，不能把一笔购买金额自动重复分配给多件物品。日均成本仅展示有价格及日期的物品，用价格除以含首日的持有天数。

每件物品当前一张图片，选择 / 拍照限制约 2048 像素、导入上限 10 MB。选择器临时结果复制为私有 `media/<UUID>` 文件，数据库只存相对路径。保存失败 / 取消可能留下孤立照片，媒体服务清理超过一天且无引用的文件。删除账目或物品不删除另一端；解除关联事务提交后原图延迟清理。

Android retrieveLostData 在物品页面首次打开时处理，恢复照片交给用户完成新的物品表单；原未保存的其他输入字段不保证恢复。

## 备份与演进

当前采用 ZIP + manifest + 逻辑 JSON + 原图，替代早期复制数据库文件 / 多文件切换的建议。全量读事务创建快照；恢复先隔离验证、发布新图片，再通过单一 SQLite 事务替换所有逻辑行。详细限制、故障保护和测试边界见 [备份协议](backup-format.md)。

Schema 与备份格式版本独立维护，目前数据库为 9、备份容器为 1，支持旧库升级与 Schema 1–9 逻辑备份恢复。v5 引入账户分类和债务账户，v6 引入余额调整，v7 引入心愿及攒钱进度，v8 引入银行，v9 引入账户归档；保留所有历史快照。不记录金额、备注、原图或备份正文到日志；测试使用人工数据。

0.2.0 的资产、图表和归档新规则以 [产品调整](../product/revision-0.2.md) 为准。
