# 开发路线与验收

当前仅完成准备工作，以下任务均未实现。阶段划分沿用 PRD；基础闭环并不等于完整 MVP。

## 准备阶段

- [x] 核对仓库状态与命令行 SDK 可用性。
- [x] 建立技术选型、依赖引入时机和版本策略。
- [x] 建立模块目录与依赖边界。
- [x] 记录金额、关联、媒体、迁移与备份设计约束。
- [ ] 确认默认货币、分类起步方式、应用组织标识。
- [ ] 配置 Flutter / Android 工具链，解析实际依赖版本。

## Phase 1：记账闭环

初始化 Android 工程 → 最小入口和导航 → 数据库 v1 与预设分类方案 → 收入 / 支出 CRUD → 日期和分类筛选 → 月度概览、分类汇总和趋势查询。

验收：真机安装运行，重启保留账目，编辑 / 删除后统计更新，历史月份查询正确。

重点验证：字符串金额转换与上限、月边界、空数据、分类类型校验、SQLite 真实持久化。图表呈现依据 UI 设计按需加入。

## Phase 2：物品基础

通过迁移增加物品及照片结构 → 物品 CRUD 与详情 → 搜索和分类 → 图片获取、持久化与清理。

验收：记录完整物品并重启，照片仍可见，删除后引用一致。

重点验证：选择器取消 / 权限拒绝 / Android 进程重建、文件失败与孤立文件清理。实现前确认最小物品字段和照片数量。

## Phase 3：购买关联

确认多物品分摊与购买关系基数 → 增加关系表 → 从支出创建并关联物品 → 已有记录关联 / 解除 → 双向详情跳转。

验收：关联不重复、不悬空；组合创建失败时全部回滚；删除一侧不会误删另一侧。

重点验证：收入不可建立购买关联、多物品关联、关联对象不存在、金额修改后的展示语义。

## Phase 4：完整 MVP

确认备份加密与替换恢复方案 → 版本化全量打包 → 隔离校验与迁移 → 数据集切换 / 回滚 → 真机稳定性及迁移验证。

验收：备份能在清空应用数据、重装或另一设备恢复；账目、物品、原图和关联一致。损坏包和恢复中断不会丢失原数据。

重点验证：金额和记录数量校对、所有照片摘要、历史 Schema、缺图、未来版本、路径穿越、解压限制、WAL 一致快照、切换各阶段故障与大数据量内存占用。

## Phase 5：iOS

Mac / Xcode 配置 → 生成并适配 iOS 工程 → 图片和文件能力验证 → iPhone 真机测试 → Android 备份导入 iOS。

验收：两个平台均能离线独立使用，业务日期、金额、图片与关联迁移一致。

## 检查策略

本阶段无代码，不新增空测试或验证占位目录的单元测试。进入实现后优先测试金额规则、实际 SQL 聚合、事务和恢复失败路径，再补关键页面与设备流程。持续集成在工程能解析、构建后配置，不能让不存在的 Flutter 工程产生虚假的通过结果。
