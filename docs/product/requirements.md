# 需求基线

来源：用户提供的《个人记账 + 记物 App 产品需求文档（PRD）》v0.1。本文为工程准备摘要，不替代原始 PRD，也不将技术建议自动视为已确认的产品决策。

## 产品目标与约束

- 面向个人使用，初期以开发者自身需求为主。
- 财务记录与物品记录可独立使用，并通过购买关联形成消费与持有之间的联系。
- Flutter + Dart，先 Android、后 iOS；核心功能离线可用。
- 数据属于用户，应支持携带图片和关联关系的备份、恢复与迁移。
- 暂不引入后端、注册登录、云同步、多人协作、OCR、AI 识别、银行同步、商业化、Web 或桌面端。

## 功能基线

| 模块 | 必须覆盖的能力 | PRD 优先级 |
| --- | --- | --- |
| 记账 | 收入 / 支出新增、查看、编辑、删除；日期排序；时间范围与分类筛选 | P0 |
| 统计 | 月收入、月支出、结余、分类支出、月度趋势、历史月份 | P0 |
| 记物 | 新增、详情、编辑、删除；名称搜索、分类筛选；照片管理 | P0 |
| 数据 | SQLite 本地存储；全量备份、校验与恢复，包含图片及关联 | P0，完整 MVP 必需 |
| 联动 | 一笔支出关联多个物品；从支出创建物品；关联账目展示和双向跳转 | P1，Phase 3 |
| 设置 | 备份、恢复、版本信息 | P0 |
| 扩展 | CSV / JSON 导出、生命周期、保修、维修、出售与持有成本 | P1 或待定 |

账目字段：ID、交易类型、金额、分类、交易日期、可选备注、创建 / 修改时间。

物品字段：ID、名称、分类、可选购买价格、可选购买日期、可选图片和备注、创建 / 修改时间。

页面范围：首页、账目列表与编辑、财务统计、物品列表与详情及编辑、设置、关联管理。导航布局和视觉风格尚未确认。

## 阶段验收

- Phase 1：Android 真机可安装；账目增删改查和基础统计可用；重启后数据保留。
- Phase 2：完整登记并重新打开一件物品，照片、搜索和分类正常。
- Phase 3：购买记录与物品建立关联，双向查看，编辑和删除后保持一致。
- Phase 4：备份可在重装或新设备恢复，包含图片与关联；验证迁移和恢复失败保护。这是首个完整 MVP 的交付边界。
- Phase 5：具备 Mac / Xcode 后完成 iOS 真机验证及 Android 数据导入。

## 保留的产品问题

- 多资金账户、资产与负债是否进入第一版？
- 预设分类还是用户可自定义分类？
- 一笔交易购买多个物品时，是否需要分摊金额，如何处理差额？
- 物品数量、品牌、型号、存放位置是否需要？
- 高级财务指标、Excel 历史数据导入是否需要？
- 备份是否加密？
- 默认货币是什么，首页偏向概览还是快捷录入？
- 产品名、视觉风格、导航结构如何确定？

以上问题不阻碍目录准备；涉及业务语义或永久应用标识的事项应在相应阶段实现前确认。
