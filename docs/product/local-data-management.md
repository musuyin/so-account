# 本地数据清空与软件重置

入口：设置 → 选项 → 数据管理。两个操作均需先阅读删除范围，再输入指定确认文字；取消、点弹窗外或输入错误文字都不执行删除。

| 操作 | 删除 | 保留／初始化 |
| --- | --- | --- |
| 清空本地数据 | 账户、流水、借贷、余额调整、预算、心愿及进度、物品、分类最近账户记忆、应用内照片及缓存 | 保留收支分类、物品种类、顺序、图标、配色、外观、自动更新偏好 |
| 重置软件 | 上述业务数据，另删除全部分类及软件设置 | 按当前安装版本重新创建默认分类，恢复默认配色、外观及更新偏好 |

清空时先将历史物品中尚未注册的种类纳入分类配置，避免清除物品后丢失这些种类。已经导出到下载目录、其他应用或外部存储的备份不会删除。两个操作都不删除系统云备份；恢复旧备份会重新带回其分类和设置。

## 使用更新后的默认分类

普通升级保留已有账本及其分类。要完全采用当前版本的默认分类，需要执行“重置软件”，而不是只清空业务数据。完成后重新进入首页，当前页面的筛选、草稿、图片缓存等会话状态一并刷新。恢复完整旧备份会再次恢复旧分类。

卸载再安装不保证获得全新数据：Android 的系统备份可在安装时恢复应用数据库，因此旧分类可能随数据库一起回来。这是平台机制上的可能原因，不能仅凭“重装后仍有旧分类”断定手机实际发生了哪种恢复；还应先在应用更新页核对已安装版本。参见 [Android Auto Backup](https://developer.android.com/identity/data/autobackup)。

## 实现与失败边界

数据库在同一事务内删除关联业务记录。完全重置在该事务中清除分类与偏好并重新播种当前默认值，Schema 仍为 9。不删除正在使用的 SQLite 文件，也不通过切换连接来绕过迁移。

删除前等待更新检查／下载退出，防止缓存或偏好在清理后被旧任务写回。数据库开启 secure_delete；提交后删除记录的应用内旧文件，执行 VACUUM 与 WAL 截断。这里的“删除”指应用所管理的数据，不承诺存储介质级取证擦除。

数据库提交前发生错误会回滚，照片尚未删除。事务中同时保存仅供本机使用的待清理凭据，且完整备份不会导出该凭据。文件删除失败会明确提示“账本已清空，但文件清理未完成”，保留重试入口；重试只清理凭据中的旧文件，不重复删除业务表。应用重新启动会先继续未完成的清理，再开放正常页面。模拟中断恢复不等同于 Android 真机进程强杀验收。

清理限制在应用媒体、缓存目录及更新偏好文件中；检查目录重叠、相对路径越界与符号链接，避免触及应用外备份或正在使用的数据库文件。
